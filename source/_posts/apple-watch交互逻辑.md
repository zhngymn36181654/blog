## 这个交互是什么

图标呈蜂巢状排列。放大点在屏幕正中心，越靠近中心的图标越大，越往四周越小。鼠标拖动，整片图标跟着平移，不同图标划过中心被放大、划走又缩小，像液体流过透镜。

日本交互设计师池田泰延（Clockmaker）2025 年重做了自己十年前的 Apple Watch 表盘 demo，作品叫 [Apple Watch UI Modoki](https://labs.clockmaker.jp/works/250909_apple_watch_modoki)。
 
## 用 GLM-5.2 复现原作者的成果

demo 编译后的 JS 只有 7KB，变量名全被压缩掉。GLM-5.2 直接读这份脚本，把原作者埋在里面的蜂巢布局、径向膨胀、随半径递减的缩放、矩形衰减这几层逻辑逐个还原出来。

## 交互模型：放大点固定在屏幕中心

放大点固定在屏幕中心，不跟着指针走。图标群整体可拖动，拖动改变的是图标群相对中心的偏移量。每一帧根据每个图标当前离中心的距离，重新算它该多大，放大跟着拖动实时变。

依据是原作者源码里那组调试矩形框 scale-boundaries，内框 216×304、外框 264×352，都用 `top:50%;left:50%` 居中在屏幕上。放大区绑在屏幕中心，不是绑在指针上。

## 蜂巢布局：271 个图标用 cube 坐标生成

蜂巢不是一圈圈画出来的，用的是六边形的 cube 坐标，三元组 `(r, i, l)` 满足 `r + i + l = 0`。半径 9 的六边形，遍历四层循环把满足条件的坐标全挑出来，一共 271 个图标。

```js
for (let u = 0; u < 10; u++)
  for (let r = -u; r <= u; r++)
    for (let i = -u; i <= u; i++)
      for (let l = -u; l <= u; l++)
        if (Math.abs(r) + Math.abs(i) + Math.abs(l) === u * 2 && r + i + l === 0)
          cubes.push([r, i, l]);
```

cube 坐标转屏幕坐标是标准的轴向投影：

```js
x = (i + r / 2) * spacing;
y = Math.sqrt(3) / 2 * r * spacing;
```

## 中心为什么不会挤成一团

中心那一片图标如果直接按原始半径排，十几个大图标会挤成一坨、彼此没缝。原作者在算每个图标位置之前，先对它离中心的半径做了一次膨胀：

```js
// M 是图标离中心的归一化半径，归一化常数 150
if (M < Math.PI / 2) {
  v = radius * g(I, M / (Math.PI / 2), 1.5, -0.5, 1);
}
```

`g(I, n, 1.5, -0.5, 1)` 展开是 `1.5 - 0.5 * I(n)`，`I` 是 easeInOutSine。中心处 `I(0) = 0`，所以 `v = 1.5 * radius`，图标被往外推到 1.5 倍远的地方。半径到 235 左右 `I` 趋近 1，`v = radius`，不再膨胀。

这一步把中心的图标撑开，大图标之间才有间距。少了它，中心就是一坨黑。

## 远处为什么自然变小

如果所有图标用同一个最大缩放，结果会是中心几个大、远处一片同样大的小点，过渡很硬。原作者给每个图标算了一个 depth（这个图标能达到的最大缩放），跟着半径递减：

```js
depth = g(C, M / (Math.PI / 2), 1, -0.5, 1);  // 展开是 1 - 0.5 * C(M / (π/2))
```

中心 `depth = 1`，半径越大 depth 越小，到 235 之后稳定在 0.5。再叠一层到边缘的衰减，远处的图标就又小又稀，整片过渡是连续的。

## 边缘按矩形衰减

缩放衰减不是按圆心距离的圆形衰减，是按一个矩形框来切的：

```js
const d = 24;
if (Math.abs(x) > W / 2 - d || Math.abs(y) > H / 2 - d) {
  scale = depth * 0.2;                                       // 外框之外，缩到 0.2
} else if (Math.abs(x) > W / 2 - 2*d && Math.abs(y) > H / 2 - 2*d) {
  scale = /* 两个方向取小 */;                                  // 角落，缓和过渡
} else if (Math.abs(x) > W / 2 - 2*d) {
  scale = depth * g($, W / 2 - Math.abs(x) - d, 0.4, 0.6, d); // 左右边
} else if (Math.abs(y) > H / 2 - 2*d) {
  scale = depth * g($, H / 2 - Math.abs(y) - d, 0.4, 0.6, d); // 上下边
} else {
  scale = depth;                                             // 内框，满血
}
```

内框（满血区）和外框（0.2 区）之间用 easeOutSine 过渡，`d = 24` 是过渡带的宽度。这套东西对应调试模式里那两个红色矩形框。

## 拖动带阻尼跟随

拖动更新一个目标偏移，渲染循环每帧把当前偏移往目标上靠：

```js
current.x += (target.x - current.x) * 0.1;
```

系数 0.1 给了一种略带滞后的丝滑感，松手之后图标群还会缓缓滑到位停下。整套跑在一个常驻的 `requestAnimationFrame` 里，每帧把这 271 个图标的位置和缩放全部重算一遍。
